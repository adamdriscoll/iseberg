# Architecture

Iseberg is a cross-platform desktop workbench inspired by PowerShell ISE.

## Module responsibilities

| Module | Responsibility |
|---|---|
| Avalonia application and `MainWindow` | Standalone desktop lifecycle, file activation, window geometry/title, initialization and close confirmation |
| `WorkbenchControl` and `WorkbenchOptions` | Embeddable workbench, host configuration, sessions/documents, layouts, menus, dialogs, keyboard routing and asynchronous lifetime |
| `WorkbenchModel` and `SessionModel` | Independent session presentation, file tabs, command history and output batching |
| `PowerShellSession` | Persistent runspace, serialized execution, asynchronous stopping, prompt refresh, completion and debugger events |
| `PowerShellSession.Debugger`, `DebuggerModels` and `BreakpointWindow` | Suspended-thread evaluation/inspection, debugger work queue, typed breakpoint descriptions/validation and live breakpoint editing |
| `PowerShellSession.Remoting`, `WorkbenchControl.Remoting` and `RemoteConnectionWindow` | Interactive runspace ownership/switching, SSH/WSMan connection UI, connection-bound remote file transfer, remote identity and source navigation |
| `WorkbenchHost` | PowerShell input, credentials, choices, output streams, console clearing and progress |
| `PowerShellSession.Nested`, `HostInputWindow` and `WorkbenchControl.Host` | Suspended-thread nested execution, typed choice/input dialogs, and cancellation-aware host/error-popup presentation |
| `TerminalApplication` and `StartTerminalCommand` | Explicit separate-terminal native execution, literal argument quoting, completion/exit-code tracking and process-tree cancellation |
| `AnsiOutputParser` | Streaming SGR styling and explicit rejection of controls that cannot safely apply to a protected transcript |
| `ScriptFile`, `ScriptEncoding`, and `ScriptTab` | Strict byte decoding/conversion, content-version save preconditions, dirty state, per-file documents, undo histories and breakpoint anchors |
| `EditorAnalysis`, editor rendering and `BreakpointMargin` | Parser-based syntax coloring, diagnostics, folding, completion context, matching-brace navigation, dedicated breakpoint gutter and theme-aware debugger highlights |
| `ConsoleBuffer` | Protected transcript and prompt, editable input, output spans and buffer limits in one text document |
| `ReplacementSearch` and `ReplaceWindow` | Literal/regex replacement, search options, selection scope and undo grouping |
| `SnippetCatalog` and `SnippetWindow` | Built-in/custom snippets, XML import/export, recursive discovery, previews, caret positioning and indentation |
| `WorkbenchControl.Scripting`, `IseSnippetService`, and `IseSnippetCommands` | Live `$psISE` subset, UI-thread document/menu adapters, owning-runspace script-block actions, session-only snippet imports and host snippet cmdlets |
| `CommandForm` and `CommandFormView` | Parameter-set metadata, per-session drafts, literal/expression serialization, required-field validation, expandable typed editors and a shared preview for pane/dialog actions |
| `CommandHelpDocument`, `CommandHelpWindow` and `HelpSettingsWindow` | Structured PowerShell help sections, selectable/read-only help presentation, literal search and zoom, isolated settings drafts and persistent help preferences |
| `UserSettings` and Options | Persisted preferences, themes, fonts, colors, completion behavior and recovery settings |
| `WorkbenchStateStore`, `ScriptRecovery`, and `WorkbenchControl.Persistence` | Configuration-only session checkpoints, separate unsaved recovery, fresh runspace restoration and window/pane geometry |
| `ThemeFile` and `ScriptPrint` | Validated versioned theme transfer and escaped offline browser print snapshots |

## Design decisions

The engine is a deep module: callers supply code and consume output/state/input/debug events. Runspace ownership, pipeline serialization, host protocol and stopping are localized there; the desktop never launches a new shell for each command. No speculative host abstraction is introduced.

`WorkbenchControl` is the UI hosting seam shared by the standalone shell and embedded hosts. It owns sessions, documents, presentation, and disposal, while the host owns initialization and containing-window lifetime. `WorkbenchOptions` snapshots presentation and persistence configuration; embedded controls default to in-memory state without application update checks. Workbench styles and system-color resources are scoped to its control/dialogs rather than written to the host application. `MainWindow` adds only desktop lifecycle, activation, geometry/title, and close orchestration. The [NuGet hosting guide](nuget-hosting.md) specifies the public interface and threading/lifetime contracts.

`WorkbenchHost` implements `IHostSupportsInteractiveSession`. A session retains its original local runspace while one pushed runspace becomes the execution/query/debugger target. Explicit connections use a default PowerShell type table so remote completion and breakpoint objects deserialize correctly. Reusable `PSSession` runspaces are borrowed; temporary interactive connections and dialog-created connections are owned and disposed on exit. The SDK's interactive ownership marker (`ShouldCloseOnPop`) is internal, so a narrowly isolated reflection read is required by the pinned SDK; a missing marker raises an explicit unsupported-SDK error rather than guessing ownership. Breakpoint specifications are keyed by runspace identity, avoiding ID collisions and preserving the local configuration. Standalone console exit commands pop on the client rather than being sent to the remote endpoint. Transport loss reports its reason and waits for the execution gate before restoring the local runspace.

Runspace-change events invalidate command forms/completion and debugger snapshots on the UI thread. Refresh waits for Ready; remote exit is a busy transition, preventing queries from racing prompt refresh. Metadata requests check runspace identity and window/session lifetime before publishing results; closing the window cancels discovery/form queries and rejects queued UI callbacks. Errors completing after closure are still traced, without trying to display a dialog against a closed owner. Remote command discovery projects only name, module, kind, and definition on the server, avoiding serialization of entire `CommandInfo` graphs and unused getters. Remote command forms project typed parameter metadata on the server into the existing description schema, rather than casting deserialized `CommandInfo` objects. Remote variables/call-stack entries are read through their serialized properties; evaluation remains on the debugger command queue and remote caller inspection is rejected explicitly.

Remote `ScriptFile` instances retain a runspace GUID and computer name plus the server's path, without local path normalization. Files travel as base64 bytes through parameterized PowerShell commands on the active runspace (or the paused debugger queue). Server-side atomic replacement preserves encoding/BOM and Unix permissions. A save acknowledges only the transmitted text snapshot after a successful write. Remote paths are excluded from local recent-file history; local/remote documents and breakpoint synchronization are separated even when paths match. Remote debugger navigation reads the server's source instead of consulting the client's filesystem. Remote breakpoint configuration is not persisted under the local tab's name.

The execution gate stays occupied while debugging. A separate work queue is drained on the `DebuggerStop` pipeline thread, where PowerShell's `Debugger.ProcessCommand` can evaluate commands and inspect suspended local scope. Paused completion invokes `TabExpansion2` on this queue, with cancellation stopping only its debugger command. Resume/stop wakes that thread and rejects queued work that no longer has a suspended scope; stop also cancels an active debugger command or graphical input request. Idle host queries and prompt refresh temporarily suppress debugging and restore the previous debug mode, so persisted command breakpoints cannot pause startup command discovery or completion/help infrastructure. User execution still honors those breakpoints; command stops without script locations remain inspectable. Break-all uses debugger step mode to suspend at the next statement, never inside an in-progress cmdlet/native command. Breakpoint mutations requested while running await a paused or finished state before using the debugger queue or idle gate; they do not automatically resume. Line synchronization preserves unchanged engine breakpoints and other breakpoint kinds. Editor anchors retain each breakpoint's condition and enabled state across text edits.

`WorkbenchControl.Debugger` owns debugger pane presentation and asynchronous inspection. The debugger occupies a full-height right-side dock alongside the independently visible Commands pane, outside the script/console layout grid. Side-pane layout collapses hidden docks and their splitters, keeps visible dividers adjacent to their panes, and retains resized widths across visibility/session changes without resetting them on inspector refresh. Session-local snapshots/watches are refreshed on pause and evaluation; resume clears variable/stack values instead of displaying stale data. Refreshes are serialized per session, and revision checks prevent late results from updating a later stop or another frame/session. Expandable tree nodes request children through pause-scoped opaque handles, bounded to 100 members per page. Handles retain original objects/PowerShell wrappers without re-evaluating the watch; getters run only when that page expands and failures become individual child values. Refresh/resume invalidates the handles.

Call-stack selection inspects the chosen frame's locals plus accessible scope variables. The engine verifies scope identity through the frame's `MyInvocation` before exposing caller variables, rejecting inaccessible dotted/module scopes rather than displaying unrelated locals. The UI labels inspection separately from evaluation: PowerShell's public debugger API does not expose switching arbitrary execution scopes, so commands, watches and completion remain in the stopped frame. Paused script completion is display-only; insertion respects the editor's read-only-section provider.

Debugger persistence lives in `UserSettings.DebuggerSessions`, keyed by PowerShell tab name. Changes and normal closure capture watches and breakpoint specifications; new numbered sessions restore matching configurations after optional profiles load. Opening a saved script reconciles its markers with restored engine breakpoints. Settings copies and Options defaults preserve debugger configuration, and atomic writes use unique temporary files. IDs, hit counts, unsaved-script markers, frames, object handles and execution state are not serialized. The breakpoint editor validates specifications before replacing an engine breakpoint, and engine breakpoint lists reconcile editor markers after debugger-console changes.

Script files retain their own text documents and undo histories. File persistence preserves recognized Unicode BOMs and line endings, marks a file saved only after a successful write, and replaces files through a temporary file in the destination directory. Explicit encoding choices use strict encoder/decoder fallbacks; legacy code pages are never inferred. Encoding changes participate in dirty state. Saved byte hashes detect external changes independently of file timestamps; saves require the original version or an explicitly confirmed destination version, checked again before replacement. Remote transfers apply the same byte-version precondition on the server. Reload updates the existing tab/document, discards undo only after successful decoding, and retains valid breakpoint specifications.

Workbench checkpoints are deliberately separate from `UserSettings.DebuggerSessions` and recovery text. They contain ordered numbered-tab names, local document paths/encoding/caret positions, selections and debugger visibility, with process identity preventing restoration of another live instance. Startup creates new engines and restores debugger specifications by name, then reads current local files and offers recovery as detached unsaved copies. Unsaved text never enters the workbench manifest; remote connection details, execution state and pause-scoped objects are excluded. Recovery records preserve encoding and owning tab name, and retain compatibility with older records. Normal closure confirms every dirty document before persisting the manifest and disposing any tab, so cancellation leaves the workbench intact.

Geometry stores normal window size/position separately from maximization and separate script ratios for top/right layouts. Layout changes capture the previous orientation before rebuilding the grid. Side-dock widths remain independent of visibility, and startup bounds window placement to an available screen. Theme imports validate a complete versioned color/font payload before modifying the Options draft. Browser printing writes only escaped text to a private offline temporary document, with cleanup on normal closure; it neither executes script text nor saves the script.

PowerShell parser tokens drive highlighting and incomplete-input detection rather than a second regex language parser. PowerShell itself supplies completion and command metadata. UI output is drained in batches and the console buffer is bounded.

`BreakpointMargin` is an AvaloniaEdit left margin, not a drawing over the text viewport. It tracks the view's visible document lines and scroll offset, aligns markers to the first row of wrapped lines, and maps left-clicks to document line numbers without moving the caret. Clicks share the F9 breakpoint path, including pause-before-edit while running. Marker hues adapt to the script background; the text renderer uses low-opacity tints instead of opaque pastel fills. Disabled breakpoints have hollow gutter markers without a line fill, and high contrast uses system-color gutter symbols without changing text backgrounds.

Command metadata is queried through the same runspace gate as completion, with cancellable, serialized requests. Alias targets supply parameter metadata while invocation retains the selected alias or module-qualified command. Forms retain values across parameter sets and sessions but serialize only the active set. Run, Insert and Copy share one generated command; literal text is quoted, and expression evaluation requires an explicit per-parameter choice. Late responses from a previous command or tab cannot replace the current form.

`CommandFormView` shares editing/validation logic between the pane's expandable controls and the standalone dialog's compact parameter-set tabs and label/value rows. Common parameters remain in a separate expander. Compact rows expose advanced inclusion/expression controls through their context menus, keeping the default form close to ISE without dropping expression or explicit-value support.

Help rendering uses PowerShell's structured properties for the ten selectable sections; it does not split formatted output on language-dependent headings. `HelpViewSettings` stores section selection, case/whole-word search and zoom, and is deep-copied with the rest of `UserSettings`. Help settings use a private draft, publish only after OK and a successful save, and preserve the previous document/preferences on save failure. The help window reuses `ReplacementSearch` for bounded literal search and the accessible editor for selectable, read-only content.

The console's `Show-Command` function delegates to a host-aware cmdlet and retains precedence when PowerShell auto-imports `Microsoft.PowerShell.Utility`. The native command otherwise tries to load WPF types unavailable to the Avalonia host. The bridge resolves metadata and help through nested invocations on the current pipeline thread, then awaits a desktop `ShowCommandRequest`. The desktop returns generated text; the cmdlet either returns it for `-PassThru` or invokes it in the current pipeline, preserving structured output and access to session variables. `-ErrorPopup` uses a current-runspace nested pipeline to collect execution error records separately from successful objects, then awaits a `CommandErrorRequest`. It does not call `ExecuteAsync` or metadata queries from the UI while holding the runspace gate. Stop cancels pending forms, input, and error popups and closes their windows.

Nested prompts retain the execution gate and drain a per-level work queue on the calling pipeline thread. `PowerShell.Create(RunspaceMode.CurrentRunspace)` executes console commands and completion against the suspended scope without racing a second pipeline. Busy frames cannot accept overlapping work; recursively entered prompts expose only the newest frame. Exit releases one frame; stop wakes and unwinds all frames and rejects stale work. Remote prompts and nesting inside debugger evaluation fail explicitly rather than mixing remoting/debugger and host queues. Debugger stops during nested command execution restore the prior host state on resume.

Input requests carry choice labels/help, defaults and a multiple-selection flag while retaining the response task shared by existing input handlers. The desktop registers handlers per session and closes dialogs when their response completes, including cancellation by Stop. Queued callbacks check session/window lifetime before opening a dialog. Single choices require a selection; multiple choices distinguish submitting no selections from accepting defaults.

`Start-IsebergTerminal` resolves a native executable and filesystem directory on the pipeline thread, then waits for a separately launched terminal. Windows uses `CreateProcessW` with `CREATE_NEW_CONSOLE` and tracks the returned process. Linux uses xterm; macOS opens a private executable `.command` file in Terminal.app. A POSIX wrapper publishes its PID and waits for an Iseberg handshake before starting the application, so cancellation cannot start an untracked native child. Atomically published status files track completion independently of terminal-launcher lifetime. Stop kills only the tracked process tree; temporary scripts/status files are removed afterward. Terminal output is deliberately outside PowerShell's structured pipeline, with an integer exit result and `$LASTEXITCODE`. No shell program is silently substituted when the configured system terminal is unavailable.

`ConsoleBuffer` localizes transcript protection, active input, prompt transitions, output spans and trimming in one document. The editor's read-only-section interface protects the transcript even when a selection spans output and input; whole-value automation writes cannot bypass it. Host changes reset console undo rather than allowing an undo operation to remove output or prompts.

Output spans retain explicit foreground/background and SGR styles. A bounded streaming ANSI parser handles split sequences and palette/true-color styling; unsupported cursor, erase and OSC controls produce a transcript warning instead of editing protected text. Prompt escapes are parsed separately so input and recalled-command offsets count visible characters, not escape bytes. Trimming preserves styling state and rebases spans; clearing resets the parser. Theme/stream colors remain fallbacks, and the renderer suppresses explicit styling in high contrast. Raw buffer dimensions are documented formatting hints; operations that imply an actual mutable terminal buffer or keyboard queue throw instead of accepting ineffective writes.

Snippet parsing and serialization are engine-independent. Import validates the PowerShell namespace/schema and metadata with DTDs/external entity resolution disabled. Stored custom snippets are plain XML, loaded without execution. The built-in catalog includes workflow/classic DSC authoring entries but labels their Windows PowerShell requirements explicitly.

The [ISE compatibility surface](ise-compatibility.md) is a desktop facade injected into each local runspace before profiles, not an emulation of the Windows PowerShell ISE assemblies. Its typed tab/file/editor wrappers dispatch workbench operations to the Avalonia UI thread and reject closed, foreign, read-only, and remote documents. File saves reuse version-checked encoding/persistence; synchronous script methods wait off the UI thread, allowing asynchronous save continuations to finish there. File removal never reenters the executing runspace gate. Custom menu trees are per-tab; the UI retains the original `ScriptBlock` and passes it to the ordinary execution path, preserving closure/module session state rather than serializing its source. The tab must be idle and local before invocation. WPF tool registration fails explicitly on every platform; no WPF dependency or binary plugin contract is added.

Host snippet cmdlets access a per-session `IseSnippetService` through `WorkbenchHostServices`, independent of the desktop facade. New files use the safe XML serializer and atomic move, refusing overwrite unless forced; Get returns user snippet `FileInfo` objects. Imports validate XML before publishing session-only entries, without executing modules or snippet code. The picker and `$psISE` snippet enumeration combine the existing saved catalog with the owning session's imports. Custom menus/imports are not serialized in workbench checkpoints.

Native title bars and file dialogs follow the host operating system.

## Compact distribution

The optional `Compact` publish profile excludes the PowerShell SDK's runtime/content assets while retaining its compile-time API references. `Program` discovers and validates an installed PowerShell before entering a non-inlined desktop/core entry point, so the JIT cannot resolve engine types before the assembly resolver is registered. Managed and native dependencies resolve from that installation using its `pwsh.deps.json`; the application and framework keep their default load-context identity.

The bundle includes its own .NET runtime and uses partial trimming for trim-compatible UI dependencies. Application/core models, AvaloniaEdit, and framework APIs are rooted because reflection bindings, JSON serialization, scripts, and external modules can access otherwise unreachable members. The engine itself is neither trimmed nor bundled. Full extraction and unmodified .NET compiler reference assemblies preserve the physical assembly paths required by PowerShell's `Add-Type`. NativeAOT is intentionally unsupported for this dynamic in-process engine.

The packaging script checks real engine behavior in both distributions, verifies an explicit missing-installation failure and a single-file compact output, compares archive sizes, and produces separate platform ZIPs. CI runs it on native x64/ARM64 hosts rather than treating a successful cross-publish as runtime verification.
