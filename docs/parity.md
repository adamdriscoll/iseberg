# ISE parity inventory

This inventory distinguishes working behavior from the full ISE surface. "Implemented" does not mean pixel-identical. The workbench uses vector icons, Avalonia controls, native OS window chrome, and installed fallback fonts.

## Not yet reproduced

- Visual presentation can differ from PowerShell ISE. Options uses compact control templates, but native chrome, installed fonts, antialiasing, DPI and accessibility text scaling can change physical pixels. Full native UI Automation text-range/navigation behavior and exhaustive screen-reader/menu interaction parity remain unverified. English resource infrastructure is implemented; translated resource packs are not included.
- Executing debugger commands/watches in a selected caller's scope. Call-stack selection changes variable inspection only; some dotted/module caller scopes cannot be verified through PowerShell's public APIs and report an inspection error.
- Nested interactive remoting, remote caller-frame variable inspection, live remote object references beyond PowerShell's serialization depth, persisted remote connections/debugger configurations, and a remote console `Show-Command` bridge. SSH/WSMan authentication and external endpoint setup require environment-specific verification; automated remoting coverage uses isolated local named-pipe servers.
- `$psISE` compatibility, WPF add-on hosting, custom menu/add-on scripting, and the ISE extension object model.
- Session restoration, external-file change detection, encoding picker/legacy code pages, printing, theme file import/export, and persisted splitter/window sizes. Recovery copies restore script text, not complete sessions or debugger state.
- Multi-choice graphical prompts, nested prompts, full character-buffer semantics, interactive native terminal applications, and complete host color/ANSI handling.
- Platform-specific installers, app bundles/signing, file associations, update delivery, and exhaustive Linux/macOS native-desktop verification.

## Intentional differences

The application hosts PowerShell 7 rather than Windows PowerShell 5.1. Windows-only modules and APIs are unavailable on other systems unless their own dependencies support those systems. ISE profiles use an Iseberg-specific host profile, and profiles are initially opt-in. Scripts run with the user's privileges; the editor is not a sandbox. Machine/user execution policy is never changed automatically.

Workflow/classic DSC templates are marked for Windows PowerShell 5.1; including them for authoring does not make their legacy syntax executable in PowerShell 7. Custom snippet files use the ISE XML format, but the ISE scripting object model and snippet cmdlets are not emulated.

The PowerShell execution gate prevents overlapping user commands and completion/metadata queries within a tab. Completion returns only when the same document/caret is still current; it does not reuse stale results. Console output is capped to keep long sessions responsive.

Paused debugger operations, including completion, are serialized on the suspended pipeline thread, rather than starting a competing runspace pipeline. Console/F8 evaluation, watch expressions and completion use the stopped scope; assignments and other side effects are real. Call-stack selection changes Variables inspection, not evaluation; the pane labels this distinction. Variables and watches expand on demand into property/dictionary/indexed children, with bounded pages, per-getter errors and references that expire on refresh/resume. Breakpoint edits requested while running first pause execution, retain the requested source line, and leave the script paused. Break-all pauses at the next PowerShell statement, not inside an in-progress cmdlet/native command. Conditions pause when true; arbitrary breakpoint actions pause only when they execute `break`. Updating an unchanged editor breakpoint retains its engine ID and hit count, and synchronizing line breakpoints does not remove command/variable breakpoints.

Debugger configurations persist by numbered PowerShell tab name in settings: watches and saved-script/command/variable breakpoint specifications, not running sessions, unsaved-script markers, engine IDs/hit counts, selected frames or object snapshots. Additional tabs restore when created; this is not full session restoration. Watch expressions and breakpoint code are stored as plaintext.

Remote documents are tied to the originating runspace instance, not just a hostname/path. Reconnect and reopen before saving or running them; local documents with the same path are distinct. Remote Save As confirms overwriting an existing destination, and named execution requires a remote file rather than interpreting a local path on the server. F8 can deliberately send local editor text to the remote runspace. Exiting restores local engine state and breakpoint specifications; remote breakpoint settings are not written into local debugger persistence. Recovery stores local plaintext copies and recovers them as unsaved, detached scripts. Credentials and connections are not restored.

The console uses a protected transcript and prompt within a single editor, not a separate input widget. Host-output/prompt changes reset console undo to prevent editing executed text; script documents retain their own undo histories. Replacement uses .NET regular expressions and bounded matching time.

Command forms use metadata from the selected PowerShell tab, not parsed help syntax. Changing parameter sets preserves entered values but only emits parameters in the selected set. Required fields and expression syntax are checked before Run/Insert/Copy; PowerShell performs type conversion and remaining attribute validation when running. Literal values are single-quoted (one array element per line), including empty optional values when explicitly included. Expression mode deliberately evaluates user-authored PowerShell. Common parameters are collapsed separately. Context-dependent dynamic parameters are limited to those PowerShell exposes when querying command metadata.

The standalone form follows the compact ISE presentation rather than duplicating the pane's expanded parameter editors. Required fields carry an asterisk, and clearing a compact text field omits it from the generated command. Right-click a parameter to expand its inclusion/expression options (including explicit empty values or a false switch). Insert is available from the dialog's context menu; the Commands pane retains its visible Insert action and preview. Ctrl+Tab/Shift+Ctrl+Tab cycles parameter sets and F1 opens the question-mark help action.

Local help comes from structured PowerShell `Get-Help` data, not English section-heading parsing. Settings independently select Synopsis, Syntax, Description, Parameters, Inputs, Outputs, Notes, Examples, RelatedLinks and Remarks; absent sections are omitted, and text-only help topics remain readable. Search operates on the displayed sections, selects each match, wraps in either direction, and applies case/whole-word preferences. Zoom and help settings persist separately from editor preferences. Native window chrome, installed fonts, PowerShell version/help content and accessibility scaling can still differ from ISE screenshots.

The hosted console supplies a `Show-Command` function that opens the same Avalonia form rather than PowerShell's Windows-only WPF dialog. `Show-Command Get-Process` runs the generated command in the originating pipeline and returns its objects; `Show-Command Get-Process -PassThru` returns the generated command text without running it. Without a name, a searchable command/module picker opens first. Cancel leaves the pipeline free to continue; Stop cancels the pending dialog and pipeline. Help is prepared on the pipeline thread so opening it never waits on the occupied runspace gate. The native `-ErrorPopup` option is not implemented; execution errors use the normal console error stream. Explicitly module-qualified native `Microsoft.PowerShell.Utility\Show-Command` still invokes PowerShell's platform-specific implementation and is not redirected.
